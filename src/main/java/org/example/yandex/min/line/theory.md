## 1. Задача

Дан массив длины `n` и окно длины `k`. Окно едет слева направо, на каждом шаге
сдвигаясь на одну позицию. Для каждого положения окна нужно вывести его минимум.

```text
массив:  4   1   3   2
окно k=2

[4  1]  3   2   → 1
 4 [1  3]  2    → 1
 4  1 [3  2]    → 2
Ответ: 1, 1, 2.
```

## 2. Две модели окна

Тут чаще всего возникает путаница. Есть две эквивалентные точки зрения,
и обе правильные. Важно не смешивать их в одной голове.

### Модель A: «окно уже стоит, растим правый край»

Мысленно поставим окно левым краем на позицию 0. Дальше на каждом шаге
правая граница сдвигается на 1, пока окно не наберёт `k` элементов.
Левая граница всё это время стоит на 0.

```text
i=0:  [4] . . .        окно растим вправо
i=1:  [4 1] . .        окно набралось (k=2)
i=2:    [1 3] .        теперь сдвигаем целиком
i=3:      [3 2]        сдвигаем дальше
```

Левая граница = `max(0, i - k + 1)`
Правая граница = `i`

До `i = k - 1` окно «неполное» — ответ не выводим.
С `i = k - 1` окно полное, и дальше обе границы едут вместе.

### Модель B: «окно уже стоит на первых k, сдвигаем целиком»

Представим, что окно изначально стоит на позициях `[0 .. k-1]`, и мы двигаем
его вправо по одному шагу. Индекс `i` — номер положения окна, а не позиция
в массиве.

```text
шаг 0: [4 1] . .       окно на позициях [0..1]
шаг 1:   [1 3] .       окно на позициях [1..2]
шаг 2:     [3 2]       окно на позициях [2..3]
```

Левая граница = `i`
Правая граница = `i + k - 1`

Окно всегда полное. Никакого «разогрева» нет.

### Что выбрать

Обе модели дают одинаковый ответ, но код получается разный.

|  | Модель A | Модель B |
|---|---|---|
| Индекс `i` означает | позицию в массиве | номер положения окна |
| Левая граница | `i - k + 1` | `i` |
| Правая граница | `i` | `i + k - 1` |
| «Окно готово» | `i >= k - 1` | всегда |
| Цикл | `for i in [0, n)` | `for i in [0, n-k]` |

Важно: если ты думаешь в модели B, а код написан в модели A — будет
казаться, что «левая граница уехала за массив» и «окно как-то странно
набирается». Это нормально. Это просто разные системы отсчёта.

В классическом коде, который ты видел раньше, используется модель A.
Сейчас разберём именно её, потому что она даёт самый компактный цикл.

## 3. Почему «в лоб» плохо

Наивное решение: для каждого окна пробежать все `k` элементов и найти минимум.

```text
окно 1: пробежали 4, 1     → 1
окно 2: пробежали 1, 3     → 1
окно 3: пробежали 3, 2     → 2
```

Сложность `O(n · k)`. При `n = 150000`, `k = 10000` — это ~1.5 млрд операций.
Слишком долго.

Хотим за один проход по массиву, `O(n)`.

## 4. Главная идея: отбрасываем бесполезные

Когда окно едет, многие числа никогда не станут минимумом. Если заранее
их отбросить, останется мало кандидатов.

Есть две причины выбросить число из рассмотрения.

### Причина №1: его перекрыл кто-то меньший справа

```text
...  5  ...  3  ...
     ↑       ↑
   было    пришло
```

5 и 3 попадают в одно окно. 3 меньше, стоит правее — значит, живёт дольше.
Пока 3 в окне, 5 бесполезно: минимумом оно не станет.

Правило: если справа пришло число меньше или равное — левое бесполезно.

### Причина №2: оно ушло из окна

```text
окно:        [1  3  2]
было:   4                   ← уже вне окна, слева
```

Число 4 раньше было в окне, но окно уехало вправо. Сейчас оно левее левой
границы, и на минимум не влияет.

Правило: если число вышло за левую границу окна — выбросить.

## 5. Что храним и где

Держим список позиций (не значений). По позиции мы понимаем, вышло число
из окна или нет.

В списке значения идут строго по возрастанию:

```text
список:   маленькое   среднее   большое
          ↑
       здесь минимум
```

Почему так: если бы шло «большое, потом маленькое» — маленькое бы выбило
большое по причине №1. Значит, такого быть не может, и остались только
возрастающие.

Следствие: минимум окна всегда в начале списка. Искать не надо.

В коде список — это `Deque<Integer>`.

- «начало списка» = «голова» = `peekFirst` / `pollFirst`
- «конец списка» = «хвост» = `peekLast` / `pollLast` / `addLast`

## 6. Три правила

Для каждого `i` от `0` до `n - 1`:

### Правило 1. Чистим хвост (перекрытие)

```java
while (!deque.isEmpty() && nums[deque.peekLast()] >= nums[i]) {
    deque.pollLast();
}
```

Пока хвост имеет значение `≥ nums[i]` — выкидываем его.

Почему `≥`, а не `>`: при равных значениях правый выгоднее: он живёт
дольше. Если оставить левый, в списке появятся дубликаты, и правило 3 будет
выкидывать не то. `≥` — правильно.

Граница: если список пуст — сравнивать не с чем, просто пропускаем цикл.
Проверка `!deque.isEmpty()` обязательна, иначе `peekLast` вернёт `null`.

### Правило 2. Добавляем

```java
deque.addLast(i);
```

Пишем `i` в конец списка.

Границы: нет. После правила 1 список может быть пуст — и это нормально,
мы его сразу наполним.

### Правило 3. Чистим голову (устаревание)

```java
if (deque.peekFirst() < i - k + 1) {
    deque.pollFirst();
}
```

Если голова строго левее левой границы окна — выкидываем.

Эквивалентная запись через «последнюю устаревшую позицию»:

```java
if (deque.peekFirst() <= i - k) {
    deque.pollFirst();
}
```

Обе формы верные. Первая читается лучше: «голова левее левой границы окна».

Почему только `if`, а не `while`: за один шаг из окна выходит не более
одной позиции — та, что была левой границей на предыдущем шаге. Значит,
хватит одной проверки. `while` тоже сработает, но это лишнее.

Граница: в списке точно есть хотя бы один элемент — мы только что добавили
`i` на шаге 2. Проверять на пустоту не нужно.

### Вывод

```java
if (i >= k - 1) {
    writer.write(Integer.toString(nums[deque.peekFirst()]));
    writer.newLine();
}
```

Пока `i < k - 1`, окно неполное — выводить нечего.

С момента `i = k - 1` окно ровно `k` элементов, и дальше каждое новое `i`
даёт ещё одно окно.

## 7. Граничные условия

Соберём всё в одном месте.

### 7.1. Где сейчас окно на шаге i (модель A)

```text
индекс:  ...  i-k  i-k+1  ...  i-1  i  i+1 ...
                ↑     ↑              ↑
           последний  ЛЕВАЯ       ПРАВАЯ
           вне окна  ГРАНИЦА      ГРАНИЦА
```

Левая граница = `i - k + 1`
Правая граница = `i`

Окно = `[i - k + 1 .. i]` — ровно `k` позиций.

«Устаревшая» позиция = `i - k` (на одну левее границы).

### 7.2. На первых шагах границы «за массивом»

На `i = 0`, `k = 3`:

```text
левая граница  = 0 - 3 + 1 = -2    (за массивом, слева)
правая граница = 0
```

Это не баг, а математическое следствие формулы. Окно «свисает» за
массив — но фактически нас интересуют только позиции `≥ 0`. Поэтому говорят
«окно неполное» — просто не выводим ответ до `i = k - 1`.

В модели A позиция `i` — это правая граница, а не левая. Левая граница
`= i - k + 1` может быть отрицательной — это нормально.

### 7.3. Сводная таблица формул

| Что | Формула | Пример: `k = 3`, `i = 4` |
|---|---|---|
| Правая граница окна | `i` | 4 |
| Левая граница окна | `i - k + 1` | 2 |
| Последняя устаревшая позиция | `i - k` | 1 |
| Голова вне окна? | `голова < i - k + 1` | `голова < 2` |
| То же самое | `голова <= i - k` | `голова <= 1` |
| Окно готово? | `i >= k - 1` | `4 >= 2` |

Совет: если запутался — подставь конкретные `k` и `i`, посчитай на бумаге.
Окно `[i-k+1 .. i]` содержит ровно `k` элементов. Это всегда так.

### 7.4. Частный случай `k = 1`

Окно из одного элемента. Минимум каждого окна — сам элемент.

Выводим с `i = 0` (потому что `i >= k-1 = 0`).

Правило 3: голова `≤ i - 1` — голова свежая (`= i`), `i <= i - 1` ложно,
ничего не выкидываем.

Читаем `nums[i]` — верно.

### 7.5. Частный случай `k = n`

Окно размером с массив. Полное окно — только на последнем шаге `i = n - 1`.
Ответ — один минимум всего массива.

### 7.6. Равные значения

Используем `>=` в правиле 1. Если равны — старый вылетает, новый остаётся.
Это гарантирует, что в списке нет дубликатов и правило 3 работает корректно.

Прогони мысленно `[2, 2, 2]`, `k = 2` с `>=` и с `>`, чтобы прочувствовать
разницу. С `>` в списке заведутся дубликаты, и голова может выкинуться
не тогда, когда надо.

## 8. Прогон на примере

`nums = [4, 1, 3, 2]`, `k = 2`.

Список пишу как `позиция:значение`. Стрелка `←` — начало списка (голова).

### i = 0, a[0] = 4

Правило 1: список пуст. Стоп.

Правило 2: `[0:4]`

Правило 3: голова `0 < 0 - 2 + 1 = -1`? Нет.

`i >= k-1`? `0 >= 1`? Нет. Не выводим.

```text
список:  ← 0:4
```

### i = 1, a[1] = 1

Правило 1: хвост `0:4`. `4 >= 1` → выкидываем. Список пуст.

Правило 2: `[1:1]`

Правило 3: голова `1 < 1 - 2 + 1 = 0`? Нет.

`1 >= 1`? Да. Ответ: `1`.

```text
список:  ← 1:1
```

### i = 2, a[2] = 3

Правило 1: хвост `1:1`. `1 >= 3`? Нет. Стоп.

Правило 2: `[1:1, 2:3]`

Правило 3: голова `1 < 2 - 2 + 1 = 1`? Нет (не строго меньше).

Ответ: `1`.

```text
список:  ← 1:1, 2:3
```

### i = 3, a[3] = 2

Правило 1: хвост `2:3`. `3 >= 2` → выкидываем. Хвост `1:1`. `1 >= 2`? Нет. Стоп.

Правило 2: `[1:1, 3:2]`

Правило 3: голова `1 < 3 - 2 + 1 = 2`? Да. Выкидываем.

Список `[3:2]`. Ответ: `2`.

```text
список:  ← 3:2
```

### Итог

Ответ: `1, 1, 2`. Совпадает с ручной проверкой.

## 9. Проверка на крайних случаях

### 9.1. Возрастающий массив `[1, 2, 3, 4]`, `k = 3`

Окна: `[1,2,3] → 1`; `[2,3,4] → 2`.

- `i=0`: список `[0:1]`
- `i=1`: хвост `1 < 2` — стоп. Список `[0:1, 1:2]`
- `i=2`: хвост `2 < 3` — стоп. Список `[0:1, 1:2, 2:3]`. Ответ: `1`.
- `i=3`: хвост `3 < 4` — стоп. Список `[0:1, 1:2, 2:3, 3:4]`.
  Голова `0 < 3 - 3 + 1 = 1`? Да → выкидываем. Список `[1:2, 2:3, 3:4]`. Ответ: `2`.

Ответ: `1, 2`. ✔

В списке всегда не больше `k` элементов, потому что все они в окне.

### 9.2. Убывающий массив `[4, 3, 2, 1]`, `k = 3`

Окна: `[4,3,2] → 2`; `[3,2,1] → 1`.

- `i=0`: `[0:4]`
- `i=1`: `4 >= 3` → выкинули. `[1:3]`
- `i=2`: `3 >= 2` → выкинули. `[2:2]`. Ответ: `2`.
- `i=3`: `2 >= 1` → выкинули. `[3:1]`. Ответ: `1`.

Ответ: `2, 1`. ✔

Здесь список никогда не длиннее одного элемента.

### 9.3. Все элементы равны `[2, 2, 2, 2]`, `k = 2`

Правило 1 с `>=` выкидывает предыдущие, каждый раз список из одного элемента.

Ответ: `2, 2, 2`. ✔

## 10. Сложность

Время: `O(n)`. Каждый индекс:

- добавляется в список один раз,
- удаляется из него не более одного раза.

Значит, суммарно `O(n)` операций на весь массив. Не зависит от `k`.

Память: `O(k)`. В списке не больше `k` элементов — все они находятся в окне.

Для сравнения: наивное решение `O(n · k)` по времени. При `n = 150000`,
`k = 10000` это разница между «мгновенно» и «секунды».

## 11. Словарик

| Слово | Что это |
|---|---|
| Очередь (deque) | Список, у которого можно брать/класть с обоих концов |
| Голова | Начало списка. Там минимум окна |
| Хвост | Конец списка. Туда добавляем новые |
| `addLast` | Добавить в конец списка |
| `pollLast` | Убрать с конца (= правило 1, перекрытие) |
| `peekLast` | Посмотреть последний, не удаляя |
| `pollFirst` | Убрать с начала (= правило 3, устаревание) |
| `peekFirst` | Посмотреть первый, не удаляя (= прочитать минимум) |
| Монотонная очередь | Очередь, в которой значения идут по возрастанию |

## 12. Шпаргалка

Один экран — всё, что нужно помнить.

```text
Правила на каждом шаге i:

  1. while deque не пуст и nums[deque.peekLast()] >= nums[i]:
         deque.pollLast()
  2. deque.addLast(i)
  3. if deque.peekFirst() < i - k + 1:
         deque.pollFirst()
  4. if i >= k - 1:
         вывести nums[deque.peekFirst()]

Границы:
  левая граница окна  = i - k + 1
  правая граница окна = i
  окно готово, когда  i >= k - 1
  окно неполное, если i < k - 1

Почему так:
  - Правило 1: новое число меньше или равно — перекрывает старое справа.
  - Правило 3: голова левее левой границы — она уже не в окне.
  - Голова списка всегда = минимум окна.
```
